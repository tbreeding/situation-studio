# Independent architecture, security, and resilience review

Status as of 2026-07-23: all high- and medium-severity local findings were
resolved; checkpoint 8 was not then authorized.

> Historical pre-deployment review. Checkpoint 8 was later authorized and
> completed as recorded in `../../HANDOFF.md`. Current unreleased overhaul
> evidence is separate and this review does not authorize another release.

Three independent reviewers assessed cross-database authority, runtime and
credential isolation, immutable history, checkout fencing, scoped variants,
crash recovery, bootstrap proof, and backup operations. The release candidate
was changed in response and the affected gates were rerun.

| Severity | Finding                                                                                               | Disposition and evidence                                                                                                                                                                                                                                                                                                                                                                 |
| -------- | ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| High     | Publication source/provenance could be supplied by a client.                                          | Closed. The server derives `CREATE`, `RESTORE`, `RETIRE`, `AGENT_ASSISTED`, or `MANUAL` from durable draft and proposal lineage. Routes no longer accept `sourceKind`.                                                                                                                                                                                                                   |
| High     | A checkout or situation fence could change between assembly and finalization.                         | Closed. The publisher verifies checkout, situation, revision, and pointer authority before promotion and again in a serializable final transaction; exactly one checkout row must be released.                                                                                                                                                                                           |
| High     | Scoped typed rows could accumulate beside the global target edge or collide on a second release.      | Closed. Candidate cloning excludes the target's superseded guide/source edge, derives unique scoped typed IDs, and recreates the target binding. A cross-database test carries one guide variant through two consecutive releases, verifies both immutable releases, verifies exact Studio/Leadership bundle hashes, and proves a second consumer remains on the unchanged global guide. |
| High     | Historical bootstrap read only the current release.                                                   | Closed. The reader enumerates every published `OFFICIAL` or `RETIRED` release, imports exact artifact bytes and bindings, deduplicates stable bundles, and has an integration proof that the enumerated set equals the database's complete recoverable release set.                                                                                                                      |
| High     | Worker and publisher claims had no durable lease recovery.                                            | Closed. Both queues use claim tokens and expirations, renew active leases, reclaim expired work, and fence late attempts. Review integration proves an expired running step resumes as a second attempt without duplicating successful stages.                                                                                                                                           |
| High     | Backup receipts were queued without a durable encrypted consumer.                                     | Closed. A dedicated consumer claims receipts with `SKIP LOCKED`, streams `pg_dump` into GPG, rechecks the final checksum, persists verified bytes, and records safe failure codes. The final disposable receipt and restore counts are in checkpoint 7.                                                                                                                                  |
| Medium   | Bootstrap read-only proof used rollback semantics without proving the ordinary role's authority.      | Closed. The proof connects as the reader role, checks `current_user`, superuser status and pointer privilege, attempts an ordinary write that must fail, rolls back the failed transaction, and compares pointer and release counts before/after.                                                                                                                                        |
| Medium   | Missing or weak browser-origin evidence could permit unsafe state-changing requests.                  | Closed. Production is HTTPS fail-closed. State changes require the configured origin; Chromium's literal `Origin: null` is accepted only for same-origin top-level navigation with matching `Host` and Fetch Metadata. Missing origin is rejected.                                                                                                                                       |
| Medium   | Parallel invalid logins could race the throttle threshold.                                            | Closed. Sorted username/IP advisory transaction locks serialize verification and failure recording. Responses remain account-indistinguishable.                                                                                                                                                                                                                                          |
| Medium   | Process configuration could expose another service's credentials.                                     | Closed. PM2 entries use distinct operating-system users; environment files are mode-0400/0600 and owned per process; the launcher clears inherited environment variables.                                                                                                                                                                                                                |
| Medium   | Runtime grants were incomplete in some paths and insufficiently demonstrated.                         | Closed. Reviewed SQL provisions owner, web, review-worker, publisher, backup-inspector, and backup-operator identities as non-superusers without database/role creation. Disposable-database proof checks required positive grants and forbidden cross-service mutations. Leadership publisher access remains append-only and promotion/restore function-mediated.                       |
| Medium   | Provider calls could ignore cancellation, leases, or unbounded responses.                             | Closed. Review calls have a 90-second abort timeout, periodic cancellation/fence/lease checks, bounded output, schema validation, safe error codes, and exact evidence hashes.                                                                                                                                                                                                           |
| Medium   | Readiness could expose raw failure details or remain healthy while reconciliation/backups were stale. | Closed. Health reports safe codes and degrades on stale process heartbeats, Leadership observation/cursor, backup verification, or recovery fencing without returning raw provider or database errors.                                                                                                                                                                                   |
| Medium   | Secret scanning did not clearly cover the repository root, fresh build output, and logs.              | Closed. The scanner resolves the repository root, scans tracked source, `.next/static`, and logs, rejects credential-shaped URLs and common key formats, and passed again after the final production build.                                                                                                                                                                              |

No unresolved high- or medium-severity finding remains in checkpoints 1–7.
This review does not authorize production migration, deployment, or a test
publication.
